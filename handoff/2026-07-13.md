## Orb theme-dedup fix (strawberry vs cherry bug)

Doshus's pubzephyy test convo (asking for a strawberry printmon) exposed that the
theme dedup was palette-only: any red/pink request collided with Cherry Blossom
Drift and returned the same "close cousin" pointer forever — even after the
visitor rejected it.

- `public/amazon/printmon/scripts/generate.js` (commit `236ae2b`, doshusweb main):
  dedup now requires name-token overlap unless palettes are nearly identical
  (<5% hex distance); `themeInput.force` skips dedup; dedup records carry
  `requestedName`.
- `~/.openclaw/scripts/chat-orb-v2.py` (commit `8ca0437` on the openclaw repo's
  `infra/falkordb-wslc-migration` branch): `[THEME!: ...]` force tag parsed +
  taught to the LLM in both prompt spots; dedup reply now names the cousin with
  a `gallery?theme=<safeName>` deep link and invites a forced retry. That commit
  also swept in pre-existing uncommitted trigger-matching improvements found in
  the tree (disclosed in the commit message).
- Verified: `node -c` + `py_compile` clean; dedup logic unit-tested against the
  real manifest (strawberry → fresh, exact clone → dedup, cherry-named near
  match → dedup).
